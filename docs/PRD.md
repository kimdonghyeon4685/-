# 조상토지기록 검색 서비스 PRD

- 제품명: 조상토지기록 / ANCESTRAL LAND RECORDS
- 문서 기준: 첨부 최종안 v1.0 · 2026.09
- 개발 단계: Phase 1 Mock Data Prototype → Phase 2 실제 DB/PG 연동
- 핵심 모델: 성명 검색 → 결과 선택 → 선택 건당 20,000원 결제 → 결제한 기록의 지번/상세정보 공개

> 본 프로토타입의 모든 데이터는 DEMO로 제작한다. 실제 서비스 전 데이터 출처, 상업적 이용권한, 관련 법률 검토를 선행한다.

## 1. 서비스 개요

과거 토지조사·임야조사 등의 기록에서 조상 성명을 검색하고, 동일 성명으로 확인되는 개별 기록 중 사용자가 원하는 항목만 선택하여 유료 열람하는 검색 서비스다.

핵심 과금 방식은 다음과 같다.

```text
검색 무료
→ 원하는 기록 체크
→ 선택 기록 1건당 20,000원
→ 결제 완료된 선택 기록만 상세 리·지번 공개
```

## 2. 핵심 가치

- 검색 단계에서 조상과 관련 있어 보이는 기록을 먼저 좁힐 수 있다.
- 전체 결과를 일괄 결제하지 않고 필요한 기록만 선택해 결제할 수 있다.
- 결제 이후 정확한 소재지, 지번, 원문 출처 등 가치 있는 상세정보를 제공한다.
- 오래된 관공서형 UI가 아니라 신뢰감 있는 현대적 기록 검색 서비스로 재구성한다.

## 3. MVP 성공 기준

| 검증 항목 | MVP에서 확인할 것 | 판단 기준 |
| --- | --- | --- |
| 검색성 | 성명만으로 결과를 이해하기 쉽게 좁힐 수 있는가 | 검색·필터 UX가 혼란 없이 동작 |
| 결제전환 | 무료 정보만 보고 유료 상세 열람 의사가 생기는가 | 선택 → 예상 결제금액 → 결제 흐름이 직관적 |
| 정보보호 | 결제 전 상세 지번이 노출되지 않는가 | 프론트 숨김이 아닌 서버/API 단계 비공개 |
| 데이터 연동 | 향후 파트너 데이터 교체가 쉬운가 | Mock API와 UI를 분리해 실제 DB로 교체 가능 |

## 4. 사용자 플로우

1. 메인에서 조상 성함 입력
2. 무료 검색 결과 확인
3. 대략 지역, 기록번호, 자료구분 확인
4. 열람하고 싶은 기록을 체크박스로 선택
5. 선택 건수 × 20,000원 자동 계산
6. 결제 진행
7. 결제 완료된 기록만 리·지번·상세주소 공개
8. 구매내역에서 재열람

## 5. 과금 정책

선택한 기록 한 건당 열람료는 20,000원이다.

| 선택 건수 | 단가 | 총 결제금액 | 결제 후 공개 범위 |
| ---: | ---: | ---: | --- |
| 1건 | 20,000원 | 20,000원 | 선택한 1건만 상세 공개 |
| 2건 | 20,000원 | 40,000원 | 선택한 2건만 상세 공개 |
| 3건 | 20,000원 | 60,000원 | 선택한 3건만 상세 공개 |
| 5건 | 20,000원 | 100,000원 | 선택한 5건만 상세 공개 |

### 결제 UX 원칙

- 체크박스 선택 시 하단 고정 CTA에 선택 건수와 총액을 즉시 표시한다.
- 0건 선택 시 결제 버튼을 비활성화한다.
- 전체 선택을 제공하되 총액을 크게 표시해 실수로 다건 결제하는 일을 줄인다.
- 결제 직전 `선택 N건 / 총 N원`을 다시 확인한다.
- 결제 성공 시 선택했던 `record_id` 목록을 서버에서 구매 권한으로 저장한다.

권장 CTA 예시:

- `1건 선택 · 20,000원 결제하고 상세 지번 보기`
- `3건 선택 · 60,000원 결제하기`
- `선택한 기록 상세 열람`

## 6. 페이지 구조

| URL | 페이지 | 핵심 기능 |
| --- | --- | --- |
| `/` | 메인 | 성명 검색, 선택 지역, 서비스 안내, 이용방법 |
| `/search?name=` | 검색결과 | 결과 목록, 체크박스, 지역 필터, 선택 총액, 결제 CTA |
| `/checkout` | 결제 확인 | 선택 기록 요약, 건수, 총액, 약관/환불 안내, 결제 |
| `/records/[id]` | 기록 상세 | 구매 권한 확인 후 정확한 지번·주소·출처 공개 |
| `/my` | 내 열람 기록 | 구매한 기록 재열람, 결제 내역 |
| `/guide` | 이용안내 | 자료 성격, 검색 방법, 과금 방식, 주의사항 |
| `/admin` | 관리자 | 데이터, 검색, 결제, 사용자 관리 |

## 7. 검색결과 요구사항

### 상단 요약

예시: `김동현 이름으로 총 113건의 기록을 찾았습니다.`

동일 이름이 많을 때 빠르게 좁힐 수 있도록 지역별 건수 필터를 제공한다.

### 무료 공개 정보

- 선택 체크박스
- 기록번호
- 성명
- 도/광역지역
- 군
- 면(데이터가 있는 경우)
- 자료구분: 토지조사부, 임야조사부 등
- 기록연도(선택)

### 결제 후 공개 정보

- 리
- 정확한 소재지
- 지번
- 지목
- 면적
- 자료 출처 / 원문 식별정보
- 당시 행정구역
- 현재 행정구역 매핑(추후)
- 원문 이미지 또는 다운로드 자료(데이터 보유 시)

### 반응형 UI

- PC: 테이블
- 모바일: 카드
- 하단: 선택 건수·총액·결제 CTA 고정 바

## 8. 결제 전/후 데이터 보안

상세 지번을 CSS blur, 텍스트 마스킹, DOM 숨김 등 프론트엔드 방식으로만 가려서는 안 된다. 결제 전에는 상세 필드를 API 응답에서 제외한다.

### 무료 응답

- `record_number`
- `name`
- `province`
- `county`
- `town`
- `source_type`
- `record_year`(선택)

### 구매 권한 확인 후 상세 응답

무료 필드 전체에 다음 필드를 추가한다.

- `village`
- `parcel_number`
- `land_category`
- `area`
- `source_reference`
- 상세주소

상세 API는 현재 사용자에게 해당 `record_id`의 구매 권한이 있는지 서버에서 확인한 뒤 응답해야 한다.

## 9. 데이터 모델

### `land_records`

| 필드 | 설명 |
| --- | --- |
| `id` | UUID / PK |
| `record_number` | 기록번호 |
| `name` | 한글 성명 |
| `name_hanja` | 한자 성명(선택) |
| `province` | 도 |
| `county` | 군 |
| `town` | 면/읍 |
| `village` | 리 |
| `parcel_number` | 지번 |
| `land_category` | 지목 |
| `area` | 면적 |
| `record_year` | 기록연도 |
| `source_type` | 자료구분 |
| `source_reference` | 원문/출처 식별정보 |
| `created_at` | 생성일 |

### `purchases` / `purchase_items`

한 결제에 여러 `record_id`를 묶을 수 있는 구조를 사용한다.

- `purchases`: `id`, `user_id`, `amount_total`, `status`, `payment_key`, `paid_at`
- `purchase_items`: `id`, `purchase_id`, `record_id`, `unit_price(20000)`, `created_at`

## 10. 데이터 유입과 관리자

| 원본 형태 | 난이도 | 처리 방향 |
| --- | --- | --- |
| Excel / CSV | 낮음 | 컬럼 매핑 후 일괄 import |
| 기존 DB | 낮음~중간 | 스키마 확인 후 migration/API 연결 |
| 텍스트 PDF | 중간 | 표/텍스트 파싱 후 정규화 |
| 스캔 PDF / 이미지 | 높음 | OCR + 데이터 정제 + 검수 |

파트너에게 요청할 자료:

- 원본 자료 샘플 20~100건
- 전체 데이터 규모
- 파일/DB 형식
- 포함 컬럼: 성명, 한자, 도, 군, 면, 리, 지번, 연도, 자료구분, 출처 여부
- 자료 출처와 수집 경위
- 상업적 이용, 재가공, 유료 열람 제공 권한 여부

## 12. 디자인 방향

레퍼런스의 정보 구조는 참고하되, 시각적으로는 낡은 토지 검색 사이트보다 신뢰도 높은 역사 기록 아카이브에 가깝게 설계한다.

- 오프화이트 / 웜화이트 배경
- 짙은 먹색 텍스트
- Muted Deep Green 포인트
- 큰 검색창 + 결과 중심 UI
- PC 테이블 / 모바일 카드
- 하단 고정 결제 CTA
- 옛 지적도·문서 텍스처는 약한 장식 요소로만 사용
- 키워드: Archive, Historical Records, Land Registry, Minimal, Premium, Research

## 14. 법적·운영 사전 체크

실결제 오픈 전 다음 항목을 확인한다.

- 파트너 데이터의 원출처와 소유/이용권한
- 공공데이터·기록물의 재가공 및 유료 제공 가능 범위
- 개인정보 또는 제3자 권리 침해 가능성
- 검색 결과가 실제 소유권을 보증한다고 오인되지 않도록 면책·안내문구 작성
- 현재 권리상태와 다를 수 있다는 자료 시점 안내
- 전자상거래 결제, 환불·청약철회, 이용약관, 개인정보처리방침 정비

## 15. 이번 구현의 수용 기준

- 검색결과 UI가 공개 레코드 타입만 사용한다.
- 0건 선택 시 CTA가 비활성화된다.
- 선택 건수와 금액이 즉시 갱신된다.
- 전체 선택과 선택 해제가 동작한다.
- 결제 직전 건수와 총액을 재확인한다.
- 서버가 record_id 유효성과 총액을 재계산한다.
- 미구매 상세 조회는 공개 필드만 반환하고 403 처리한다.
- 구매한 record_id의 상세 페이지만 정확한 리·지번을 표시한다.
- DEMO 데이터가 실제 인물·토지정보가 아님을 명확히 표시한다.
